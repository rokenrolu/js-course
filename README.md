4. false 0 '' null undefined NaN
5. оба вернут "нет"  || возвращает второй операнд для любого ложного первого ?? возвращает второй операнд только для null/undefined; здесь первый — '', но результат всё равно 'нет', потому что '' не null и не undefined
6. Number преобразует строку целиком и при любом постороннем символе даёт NaN → Number('12px') === NaN parseInt читает слева направо до первого нецифрового символа и молча отбрасывает остаток → parseInt('12px') === 12
7. массив хранится в памяти отдельно, а переменная содержит ссылку на него b = a копирует ссылку, а не массив, поэтому a и b указывают на один объект настоящая копия — через [...a]
8. произойдёт fall-through после совпадения выполнится код подряд до первого break или конца switch, включая следующие case/default, без проверки условий
9. scope — локальные и замыкающие переменные в текущей точке останова (раздел Local, Closure, Global) с их значениями
watch — произвольные выражения, которые вы добавили для постоянного наблюдения (например, typeof total); обновляются на каждом шаге
call stack — цепочка активных вызовов функций (кто кого вызвал), позволяющая понять, откуда пришли в текущую строку


контрольные вопросы 2
1. Declaration — это function f() {} как отдельная инструкция: имя и тело создаются на этапе подготовки контекста, поэтому функцию можно вызвать до объявления (hoisting). Expression — это const f = function () {} / const f = () => {}: функция создаётся в момент выполнения строки, имя появляется только после присваивания, до этого — TDZ (let/const) или undefined (var). Declaration имеет собственное имя и подходит для рекурсии; expression часто анонимно и удобно как значение/callback
2. Если аргумент не передан, параметр получает undefined. Значение по умолчанию (function f(x = 10)) подставляется только когда аргумент не передан или явно равен undefined. null, 0, '', false — это переданные значения, подстановки не происходит
3. console.log только печатает значение в консоль и возвращает undefined; вызывающий код результата не получает. return завершает функцию и передаёт значение в место вызова, его можно присвоить, сложить, передать дальше. Функция без return возвращает undefined
4. Фигурные скобки после стрелки воспринимаются как тело функции, а не как объектный литерал. Внутри name: — это метка (label), тело ничего не возвращает, поэтому результат undefined. Чтобы вернуть объект, его заключают в круглые скобки: () => ({ name: 'x' })
5. Лексическое окружение — хранилище переменных, создаваемое при вызове функции/блока, со ссылкой на внешнее окружение. Поиск имени идёт по цепочке: текущее окружение → внешнее → … → глобальное; останавливается на первом найденном. Поэтому внутренние функции видят внешние переменные, а снаружи локальные не видны
6. Замыкание — функция вместе с лексическим окружением, в котором она была создана. Внутренняя функция хранит ссылку на окружение createCounter, поэтому после его завершения окружение не уничтожается сборщиком мусора, пока жива функция. Так count остаётся доступной и защищённой от внешнего кода
7. В начале строки function воспринимается как объявление функции, а объявление без имени — синтаксическая ошибка. Внешние скобки превращают объявление в выражение, после чего () сразу его вызывают: (function () { … })();
8. Стек вызовов — структура LIFO, где каждый вызов функции добавляет кадр (параметры, локальные переменные, адрес возврата). Без базового случая рекурсия добавляет кадры бесконечно, пока не исчерпает отведённую память стека (обычно ~10 000 кадров). Движок выбрасывает RangeError: Maximum call stack size exceeded
9. На этапе подготовки контекста объявления function создаются целиком (имя + тело) и помещаются в окружение. Для const/let имя регистрируется, но значение появляется только при выполнении строки объявления; до неё переменная в «временной мёртвой зоне» (TDZ), обращение даёт ReferenceError
10. Объект хранится в памяти, а переменная содержит ссылку на него. При вызове копируется ссылка, поэтому параметр и внешняя переменная указывают на один объект — изменение поля меняет общий объект. Присваивание item = {...} записывает в параметр новую ссылку, внешняя переменная по-прежнему указывает на старый объект, поэтому снаружи изменений нет. В JS всё передаётся по значению, но для объектов значением является ссылка

контрольные вопросы 3
1. Через точку обращаются только к ключу, являющемуся правильным идентификатором (без пробелов, дефисов, не начинается с цифры). Квадратные скобки принимают любое выражение: строку с пробелом (obj['in stock']), переменную (obj[field]), вычисляемое значение. obj.key — это фактически obj['key'] для литерального имени
2. this определяется в момент вызова по правилу «объект слева от точки»: в obj.method() this === obj. Если метод сохранить в переменную и вызвать fn(), слева от скобок объекта нет — в строгом режиме this === undefined (в нестрогом — глобальный объект). Метод «теряет» объект, потому что связь с ним существовала только в выражении вызова через точку
3. У стрелочной функции нет своего this: она берёт его из окружающей лексической области видимости (как обычную переменную). У обычной функции this определяется при вызове (объект слева от точки, call/apply/bind, new, иначе undefined/глобальный объект). Поэтому стрелочные удобны для callback внутри методов
4. Поверхностная копия ({...obj}, Object.assign) создаёт новый объект и копирует свойства первого уровня: примитивы — по значению, объекты — по ссылке. Вложенный объект остаётся один на всех, поэтому изменение его полей через копию видно в оригинале. Для независимой копии нужна глубокая (structuredClone)
5. === для объектов сравнивает ссылки (адреса в памяти), а не содержимое. Два литерала {a:1} создают два разных объекта в куче с разными ссылками. Равны только переменные, указывающие на один и тот же объект. Для сравнения по содержимому нужна своя функция (или JSON.stringify/рекурсивное сравнение).
6. Создаёт новый пустой объект
Связывает его прототип с Constructor.prototype
Вызывает функцию-конструктор, подставив новый объект в this
Возвращает этот объект (если конструктор не вернул другой объект явно)
7. Прототип — объект, на который ссылается другой объект (скрытая ссылка [[Prototype]]). При чтении свойства движок сначала ищет его в самом объекте; если не находит — переходит к прототипу, затем к прототипу прототипа и так до Object.prototype, затем до null. Если не найдено нигде — undefined. Запись свойства всегда создаёт его в самом объекте (затеняя прототип)
8. call(thisArg, a, b) — сразу вызывает функцию с заданным this, аргументы через запятую
apply(thisArg, [a, b]) — сразу вызывает, аргументы массивом (или array-like)
bind(thisArg, a, b) — не вызывает, а возвращает новую функцию с навсегда привязанным this (и частично применёнными аргументами)
9. writable — можно ли менять значение (false → только чтение)
enumerable — видно ли свойство в Object.keys, for…in, JSON.stringify
configurable — можно ли удалять свойство и менять его флаги/тип (геттер↔значение)
У свойств, созданных присваиванием, все три true; в defineProperty неуказанные флаги по умолчанию false
10. const запрещает только переприсвоить имя переменной, но объект по ссылке можно менять (добавлять/удалять/изменять свойства). Object.freeze делает все свойства недоступными для записи и запрещает добавление/удаление свойств (в строгом режиме — TypeError). Заморозка поверхностная, потому что freeze обрабатывает только собственные свойства объекта: вложенные объекты остаются изменяемыми (замораживается лишь ссылка на них). Для полной защиты нужна рекурсивная deepFreeze
